改进方向 LAM 数据流详细分析

基于架构图中"多主体感知 + 多向量输出（无监督）"的改进方向，以具体视频为例逐步追踪数据流

示例视频场景

一个 256×256 的视频，包含 3 个彩色方块（红、绿、蓝）在棋盘格背景上运动。
视频共 5 帧，每帧 256×256 RGB。3 个方块分别执行不同的动作（向右、向上、静止）。

模型配置：patch_size=16, model_dim=256, latent_dim=32, max_actors=3
Batch：B=2（2 个视频一起训练）

与当前代码实现的关键区别：
• 主体数 A=3 + 背景槽 = A+1=4 个对象槽（当前代码无背景槽）
• 逐帧检测模块（YOLO/LocateAnything）生成 mask（当前代码用 GT mask）
• 对象级时空注意力处理 (A+1)×T 二维矩阵（当前代码用简单 Transformer Self-Attention）
• Per-Object VAE 输出多向量 (A+1)×z̃ ∈ R³²（当前代码也是多向量，两者一致）
• 无监督训练：L = L_recon + β·KL + λ·L_obj_recon，不依赖动作标签

# 视频帧：5帧，每帧 256×256 RGB，float32 [0,1]

# B=2, T=5, H=256, W=256, C=3
与原始相同 输入只有视频帧，不需要预先提供 GT mask。 mask 将由步骤 2 的检测模块自动生成。

2 逐帧检测：识别并分割画面中的主体 新增

# 对每一帧独立运行检测模型
# 方案 A：YOLO 检测 → bbox → 填充为矩形 mask
# 方案 B：LocateAnything → bbox → SAM2 → 精确像素级 mask

# 以 YOLO 方案为例：
# 对 videos[b, t] 运行 YOLO，得到 K 个 bbox + 类别
# 用 ByteTrack 跨帧关联，分配 track ID
# 将 bbox 填充为二值矩形 mask

# 检测结果：
detected_masks.shape = (2, 5, 3, 256, 256) ← 检测生成
# B=2, T=5, A=3, H=256, W=256
# detected_masks[b, t, a] = 第b个视频、第t帧、第a个主体的检测mask
# 例如 detected_masks[0, 0, 0] = 红色方块的矩形mask

# 同时构造背景mask：
bg_mask = 1 - detected_masks.sum(dim=2, keepdim=True).clip(0, 1)
bg_mask.shape = (2, 5, 1, 256, 256) ← 背景槽

# 合并：背景 + 主体 → A+1 个对象槽
all_masks = cat([bg_mask, detected_masks], dim=2)
all_masks.shape = (2, 5, 4, 256, 256) ← 含背景
# 第0个槽 = 背景，第1-3个槽 = 红/绿/蓝方块
检测模块的作用：将"哪些像素属于哪个主体"这个先验知识注入模型。
背景槽：背景也占一个槽位，确保背景区域的特征不被忽略。

与当前代码的区别：当前代码直接使用 GT mask，且没有背景槽。 改进方向用检测模型自动生成 mask，并显式加入背景槽。

3 Patchify + SpatioTemporal Transformer 编码

# 1. Patchify：将视频帧切分为 patch
# patch_size=16, 每帧 16×16=256 个 patch，每个 768 维
patches = patchify(videos, patch_size=16)
patches.shape = (2, 5, 256, 768)
# B=2, T=5, N=256, D_patch=768

# 2. SpatioTemporal Transformer 编码（与原始 AdaWorld 完全相同）
# 768 → 256 维，4个block
# 每个block: Spatial Attn + Temporal Attn + FFN
encoded = self.encoder(patches)
encoded.shape = (2, 5, 256, 256)
# B=2, T=5, N=256, model_dim=256
# encoded[b, t, n] = 第b个视频、第t帧、第n个patch的256维特征
与原始相同 编码器结构完全不变。
关键区别：原始 LAM 在 patchify 后拼接 action_prompt token（257 个 token）， 编码后提取 prompt 输出作为隐动作。改进方向不拼接 prompt，编码后用 mask 池化提取主体特征。
编码器做了什么？
Spatial Attention：每个 patch 可以"看到"同一帧内所有其他 patch → 捕捉空间关系
Temporal Attention：每个 patch 可以"看到"其他帧同一位置的 patch → 捕捉时序变化
经过 4 层后，每个 patch 的特征已经融合了全局时空信息。
↓

4 Mask Pooling：按对象槽池化 patch 特征（含背景） 新增

# 1. 将 mask 下采样到 patch 级别
# all_masks: (2, 5, 4, 256, 256) → adaptive_avg_pool2d → (2, 5, 4, 16, 16) → flatten
masks_down.shape = (2, 5, 4, 256)
# masks_down[b, t, a, n] = 第a个对象槽在第n个patch区域的占比
# 例如 masks_down[0, 0, 0, 42] = 0.0 表示背景不覆盖第42号patch
# masks_down[0, 0, 1, 42] = 0.85 表示红色方块覆盖了第42号patch的85%

# 2. 加权平均池化
# weights = masks_down.unsqueeze(-1) → (2, 5, 4, 256, 1)
# feat = encoded.unsqueeze(2) * weights → (2, 5, 4, 256, 256)
# obj_feats = feat.sum(dim=-2) / mask_sum → (2, 5, 4, 256)

obj_feats, valid_mask = self.mask_pool(encoded, all_masks)
obj_feats.shape = (2, 5, 4, 256) ← 含背景槽
# B=2, T=5, A+1=4, model_dim=256
# obj_feats[b, t, 0] = 背景的256维聚合特征
# obj_feats[b, t, 1] = 红色方块的256维聚合特征
# obj_feats[b, t, 2] = 绿色方块的256维聚合特征
# obj_feats[b, t, 3] = 蓝色方块的256维聚合特征

valid_mask.shape = (2, 5, 4)
# valid_mask[b, t, a] = True/False，该对象槽在该帧是否存在
# 背景槽始终 valid=True
Mask Pooling 的直觉：把属于同一个对象（主体或背景）的所有 patch 特征加权平均，得到该对象的"整体特征"。

与当前代码的区别：当前代码只池化主体（A=3），没有背景槽。 改进方向加入背景槽（A+1=4），确保背景区域的特征也被显式建模。

5 对象级时空注意力：主体间交互 + 时序动态 新增

这是最核心的改进步骤。对上面的 (A+1)×T 二维特征矩阵施加时空自注意力， 让不同对象槽之间和不同时序之间充分交互。
# 将 (B, T, A+1, D) 重排为 (B, (A+1)*T, D) 的序列
# 每个样本 = 4个对象槽 × 5帧 = 20个token
seq = obj_feats.reshape(2, 20, 256) # (2, 20, 256)

# 对这个 20-token 序列做 Transformer Self-Attention
# 注意力模式：
# - 同一帧内跨对象槽：背景↔红块↔绿块↔蓝块（空间注意力）
# - 同一对象跨帧：红块@t0↔红块@t1↔...↔红块@t4（时间注意力）
# - 全交互：任意token可以attend到任意其他token

obj_feats_refined = self.obj_st_attention(seq, padding_mask=...)
obj_feats_refined.shape = (2, 20, 256) ← 新增

# 重排回 (B, T, A+1, D)
obj_feats_refined = obj_feats_refined.reshape(2, 5, 4, 256)
obj_feats_refined.shape = (2, 5, 4, 256)
# 形状不变，但每个对象槽的特征已经融合了：
# - 其他对象在同一帧的信息（主体间交互）
# - 自身跨帧的动态信息（时序动态）
注意力交互模式示意（以红块@t2 为例）
空间注意力（同一帧跨主体）
红块@t2 关注同帧其他对象
深红=自身，浅红=同帧交互
时间注意力（同一主体跨帧）
红块@t2 关注自身其他帧
深红=自身，蓝色=同主体跨帧
全交互（任意token间）
标准 Self-Attention 全连接
紫色=全交互，红=自身
与原始 LAM 的区别 原始 LAM 的 SpatioTemporal Transformer 在 patch 级（144 tokens）做时空注意力。 改进方向在对象级（4 tokens）做时空注意力——粒度更粗但语义更明确， 且同时建模主体间交互关系和主体自身的时序动态。
为什么在特征空间而非隐动作空间做交互？
1. 特征空间维度更高（256 vs 32），信息更丰富
2. 时空注意力让每个对象槽同时理解"其他主体在做什么"和"自己随时间如何变化"
3. 类比：原始 LAM 的 SpatioTemporal Transformer 在 patch 级做时空注意力；
    改进后在对象级做时空注意力——粒度更粗但语义更明确
↓

6 Per-Object VAE：每主体独立编码，输出多向量 新增 · 关键

# 1. Per-Object VAE：每个对象槽（含背景）独立编码
# 输入 obj_feats[:, :-1]（前 T-1 帧），与 Decoder 对齐
# (2, 4, 4, 256) → 每个对象槽独立过 VAE → (2, 4, 4, 32)
B, T1, A1, D = obj_feats_in.shape # (2, 4, 4, 256)
feat_flat = obj_feats_in.reshape(-1, D) # (B*T1*A1, 256) = (32, 256)
moments = self.vae_fc(feat_flat) # (32, 64)
z_mu, z_var = chunk(moments, 2, dim=-1) # 各 (32, 32)
z_rep = z_mu + noise * exp(0.5 * z_var) # (32, 32) 重参数化

# 重排回 (B, T-1, A+1, latent_dim)
z_rep = z_rep.reshape(B, T1, A1, -1)
z_rep.shape = (2, 4, 4, 32) ← 多向量输出
# B=2, T-1=4, A+1=4, latent_dim=32
# z_rep[b, t, 0] = 背景的32维隐动作（通常接近零）
# z_rep[b, t, 1] = 红色方块的32维隐动作（= 向右运动）
# z_rep[b, t, 2] = 绿色方块的32维隐动作（= 向上运动）
# z_rep[b, t, 3] = 蓝色方块的32维隐动作（≈ 零向量，静止）

# 2. 对象级重建头：从隐动作预测下一帧特征（无监督学习信号）
# z_rep 编码了 obj_feats[:, :-1] 的信息，预测 obj_feats[:, 1:, 1:, :]
z_actors = z_rep[:, :, 1:] # (2, 4, 3, 32) 不含背景
next_feat_pred = self.obj_recon_head(z_actors) # (2, 4, 3, 256)
next_feat_target = obj_feats[:, 1:, 1:, :] # (2, 4, 3, 256)
L_obj_recon = MSE(next_feat_pred, next_feat_target.detach())
# 仅对主体（不含背景）计算对象级重建损失
Per-Object VAE 的设计思想：每个对象槽独立编码，不进行跨槽聚合。
每个主体的隐动作 z̃ ∈ R³² 编码了该主体的运动信息。

与当前代码一致 当前代码也输出多向量 (B, T-1, A+1, 32)。

对象级重建头：从隐动作预测下一帧的每主体特征，提供无监督学习信号， 鼓励隐空间保留每个主体的运动信息，有效缓解后验坍缩。
↓

7 Decoder：用多 slot 隐动作重建视频帧

# 多 slot Cross-Attention 解码

# 1. 将 patch 特征和隐动作映射到相同维度
video_patches = self.patch_up(patches[:, :-1]) # (2, 4, 256, 256)
action_embed = self.action_up(z_rep) # (2, 4, 4, 256) ← A+1 slots
# 32维隐动作 → 256维，A+1个slot

# 2. Cross-Attention: patch 作为 query，A+1个动作embed 作为 key/value
B_s, T1_s, _, D_m = video_patches.shape
v_p = video_patches.reshape(B_s*T1_s, -1, D_m) # (8, 256, 256)
a_e = action_embed.reshape(B_s*T1_s, A1, D_m) # (8, 4, 256) ← 多slot
fused = self.cross_attn(q=v_p, kv=a_e) # (8, 256, 256)

# 3. 残差连接 + SpatioTransformer 解码
video_action_patches = fused + video_patches # 残差
recon_patches = self.decoder(video_action_patches) # (8, 256, 768)
recon = unpatchify(recon_patches, 16, 256, 256) # (2, 4, 256, 256, 3)
recon = sigmoid(recon)
recon.shape = (2, 4, 256, 256, 3)
# B=2, T-1=4, H=256, W=256, C=3
与原始 LAM 不同 原始 LAM 用 1 个动作 slot 做 Cross-Attention。
改进方向用 A+1=4 个动作 slot，每个对应一个对象槽的隐动作。
Cross-Attention 让每个 patch 可以"关注"到所有对象槽的隐动作，
解码器需要决定每个 patch 主要受哪个主体影响，自动完成空间分配。

原始 LAM

1 个动作 slot → Cross-Attn
a_e: (8, 1, 256)
单slot，全局压缩

改进方向

A+1 个动作 embed → Cross-Attn
a_e: (8, 4, 256)
多slot，逐主体独立

8 损失函数（无监督）

# 1. 重建损失（场景级，与原始相同）
L_recon = MSE(recon, videos[:, 1:])
# recon: (2, 4, 256, 256, 3) vs videos[:, 1:]: (2, 4, 256, 256, 3)

# 2. KL 散度（A+1 个独立 KL）
L_KL = Σa KL(q(z̃a | obj_feats_ina) || p(z̃a))
# Per-Object VAE 每个对象槽有独立的 KL

# 3. 对象级重建损失（无监督学习信号）
L_obj_recon = MSE(next_feat_pred, next_feat_target.detach())
# 从隐动作预测下一帧的每主体特征

# 4. 总损失（无动作监督）
L = L_recon + β · L_KL + λ · L_obj_recon
# β: KL annealing, λ: obj_recon_weight
与原始 LAM 不同 原始 LAM 只有重建 + KL。
改进方向新增 对象级重建损失，在每个主体隐动作上施加特征空间重建任务。
关键优势：obj_recon 防止后验坍缩，隐方差从 2 提升到 20+。
无监督：不依赖任何动作标签，完全自监督。

VAE 结构 单 VAE（1 个隐向量） Per-Object VAE（A+1 个隐向量） 每主体独立编码

改进方向的核心原则：显式分离主体，多向量输出（无监督）

新增部分（步骤 2, 4, 5）：检测分割 → 主体级特征 → 时空交互
保留部分（步骤 3）：原始编码器不变
关键变化（步骤 6, 7, 8）：Per-Object VAE → 多向量 (A+1)×z̃ ∈ R³²
训练目标：L_recon + β·KL + λ·L_obj_recon，无动作监督

类比：原始 LAM 的 action_prompt 是"盲人摸象"——1 个 token 必须从全局 attention 中猜测哪里有运动。
改进后：先用检测"看见"每个主体，再让它们交互，每个主体独立的隐动作。——分工精细，输出丰富，但世界模型需要适配。
与下游世界模型的衔接

多向量输出 (A+1)×z̃ ∈ R³² 无法直接接入原始世界模型的 crossattn(B,1,32)+vector(B,32) 接口。
可行适配方案：
A. Mean Pool 聚合：z̃ = mean(z̃₀, ..., z̃ₐ) → R³²，兼容但可能丢失信息
B. 多条件注入（待实现）：每个主体 crossattn + vector 分通道注入
C. 主体选择：只取运动最大的主体
当前阶段：仅验证隐动作空间的结构性，暂不接入世界模型
