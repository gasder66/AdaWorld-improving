原始架构核心设计

信息瓶颈：1 个 action_prompt token → 32 维隐向量。Prompt 必须从两帧交互中"压缩"出最关键的动作信息。
编码方式：SpatioTemporal Transformer 让 prompt 与所有 patch 做 attention，隐式地聚合全局信息。
输出接口：z̃ ∈ R32 → 直接作为世界模型的 crossattn + vector 条件。

改进方案核心思路

关键原则：显式分离主体，多向量输出（无监督）

新增部分（步骤 2, 4, 5）：检测分割 → 主体级特征 → 时空交互
保留部分（步骤 3, 7）：原始编码器和解码器不变
关键变化（步骤 6）：Per-Object VAE → 多向量 (A+1)×z̃ ∈ R32，每个主体一个隐动作向量
训练目标：仅 Lrecon + β·KL + λ·Lobj_recon，无动作监督

类比：原始 LAM 的 action_prompt 是"盲人摸象"——1 个 token 必须从全局 attention 中猜测哪里有运动。
改进后：先用检测"看见"每个主体，再让它们交互，每个主体独立的隐动作。——分工精细，输出丰富，但世界模型需要适配。

五、核心问题与当前判断

问题 1：改进方案的有效性

实验结论：多向量无监督 v2（recon + KL + obj_recon）训练后：
ARI(动作聚类) = 0.0003（≈ 随机），线性探针 = 44.1%（略高于随机基线 20%）
隐方差 = 20.5（解决了后验坍缩），但隐空间未对齐到离散动作类别
当前判断：改进方案在无监督下未产生结构化的隐动作空间

问题 2：为什么重建任务不足以驱动动作分离？

原因分析：重建任务只需要隐向量编码"帧间特征变化"（连续运动信号），
不要求编码"上/下/左/右"这类离散语义类别。
每个主体的隐向量可能编码了精细的像素级偏移量，但对线性分类器来说这些偏移量并不聚集为 5 类。
总结：重建驱动的隐动作是连续空间，不是离散聚类空间

问题 3：多向量输出与 AdaWorld 的衔接

当前状态：多向量输出 (A+1)×32 无法直接接入原始世界模型的 crossattn(B,1,32)+vector(B,32) 接口。
可行方案：（A）Mean Pool 聚合回单向量 → 兼容但可能丢失信息；
（B）重新设计世界模型的多条件注入 → 工作量较大；
（C）只取运动最大主体的隐向量 → 简单但浪费信息。
当前阶段：先验证无监督隐动作空间的结构性，再考虑世界模型适配

下一步建议

方向 1：增加 obj_recon_weight 或调整 KL beta，探索是否能改善隐空间结构
方向 2：尝试更大 KL beta（如 β=0.001），更紧的信息瓶颈可能迫使隐向量编码更抽象的信息
方向 3：回到原始 LAM 的单向量模式，先用合成数据验证多主体场景是否真的有问题
方向 4：考虑 InfoNCE / 对比学习等替代损失函数，直接鼓励同动作隐向量靠近
